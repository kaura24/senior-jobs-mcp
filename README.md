## 왜 이걸 만드는가

| | | |
|---|---|---|
| **1,012만 명** | **41.6%** | **30분 → 3분** |
| 2026년 5월, 55~79세 고령층 취업자가 사상 처음 1,000만 명 돌파. 69.2%는 계속 일하기를 희망 | 시니어 구직자의 41.6%는 여전히 공공 취업알선기관에 직접 가서 묻는다. 공고는 있지만, 찾을 수 없기 때문 | 김영희(68세)는 47개 공고를 하나씩 열어보며 30분을 썼다. 절반은 마감된 공고였다 |

시니어 구직자가 겪는 현실은 네 가지다.

- **공고는 분산되어 있다.** 노인일자리여기, 고용24, 복지로, 지자체 사이트 — 어디서부터 찾아야 할지 모른다.
- **마감된 공고가 섞여 있다.** 검색 결과에 마감된 공고가 버젓이 나온다. 일일이 열어봐야 알 수 있다.
- **검색이 어렵다.** 복잡한 필터, 생소한 용어. "나에게 맞는 일자리"를 찾는 건 고역이다.
- **고정관념이 있다.** 기존 서비스는 시니어를 "단순 업무" 대상으로만 취급한다. 개인의 경력과 선호는 반영되지 않는다.

> **핵심 질문 — "어느 동네에서, 뭘 하면서 일하고 싶으세요?"**
>
> 이 질문에 답하면, 현재 지원 가능한 일자리를 정확히 안내해주는 서비스가 없을까?

### 기존 서비스의 빈틈

| | 당근알바 | 사람인 AI | 고용24 기존 | **본 서비스** |
|---|---|---|---|---|
| 대상 | 전 연령 | 전 연령 | 전 연령 | **60세+ 시니어 특화** |
| 탐색 방식 | 키워드·필터 | 이력 기반 | 역량 기반 | **대화형 조건 탐색** |
| 유효성 검증 | 마감 공고 노출 | 마감 공고 노출 | 마감 공고 혼재 | **규칙 기반 원천 차단** |
| 편향 방지 | 없음 | 없음 | 없음 | **프롬프트 레벨 강제** |
| 추천 근거 | 없음 | "AI 추천"만 | 없음 | **조건별 일치 근거 명시** |

기존 서비스는 "찾는 사람"을 전제로 한다. 본 서비스는 "찾기 어려운 사람"을 전제로 한다. 접근성 자체가 기능이다.

## 어떤 기술을 이용하는가

### 규칙 + AI 하이브리드 아키텍처

**규칙은 정확성을, AI는 유연성을 담당한다.**

```
[사용자] ⇄ [대화형 UI] ⇄ [AI 엔진] ⇄ [공고 검증 모듈] ⇄ [SenuriService API]
                                              ↓
                                    [유효 공고 마스터]
```

#### 규칙이 담당하는 것 — 정확성

공고 유효성 판정, 중복 제거, 날짜 정규화. 이 영역은 AI의 판단에 맡기지 않는다.

| 검증 항목 | 규칙 |
|---|---|
| 모집 상태 | 원천 상태가 명시적으로 '접수중'이어야 함 |
| 접수 기간 | 시작일 ≤ 오늘 ≤ 종료일 (Asia/Seoul 기준) |
| 날짜 유효성 | '상시'·누락·잘못된 날짜·시작일 > 종료일은 제외 |
| 상태 충돌 | 목록과 상세의 상태·기간이 충돌하면 제외 |

#### AI가 담당하는 것 — 유연성

- **모호한 조건의 해소** — "오전 시간대"를 구체 시간으로, "집 근처"를 이동 가능 범위로 변환
- **개인화 질문 전략** — 후보 분포를 보고 다음에 물을 가장 유용한 질문을 동적으로 선택
- **근거 문장 생성** — "왜 이 공고인지"를 사용자의 조건에 맞춰 자연어로 설명
- **편향 방지** — 연령 고정관념이 개입할 여지를 프롬프트 레벨에서 차단

> "나이를 이유로 디지털 능력, 체력을 추정하지 않는다" — 프롬프트에 명시된 기술적 제약.
> 철학적 선언이 아니라 모델 출력 레벨에서 강제되는 규칙이다.

### MCP 도구

| 도구 | 용도 |
|---|---|
| `describe_search_options` | 저장 데이터 기반 선택지·분포·누락 항목 |
| `search_jobs` | 현재 희망조건으로 저장 공고 검색·페이지 조회 |
| `get_job_details` | 선택한 실제 공고 ID의 저장 목록·캐시 상세 요약 |

**운영 주소:** `https://senior-jobs-poc-mcp.vercel.app/api/mcp`

MCP는 인증 없이 JSON-RPC POST를 받는다. 조회는 저장된 스냅샷만 사용하며, 조회 시 KST 접수기간을 다시 판정한다.

## 어떤 효용을 주는가

### 세 가지 원칙

1. **정확성** — 유효 공고만 추천한다. 마감됐거나, 시작 전이거나, 날짜가 불명확한 공고는 절대 추천하지 않는다.
2. **존중** — 연령 고정관념을 배제한다. "시니어니까 단순 업무" 같은 편견을 사용하지 않고, 개인의 조건과 선호를 있는 그대로 반영한다.
3. **투명성** — 근거 있는 추천을 한다. 모든 추천에 "왜 이 공고인지" 근거를 명시하고, 확인되지 않은 정보는 "공고에 미기재"로 표시한다.

### 기대 효과

- **탐색 시간 단축** — 수십 개 공고 수동 확인에서 대화 3분 내 유효 공고 3~5개 추천으로
- **신뢰 향상** — 투명한 근거 제시로 "왜 이 공고인지"를 항상 설명
- **디지털 포용** — 복잡한 검색 대신 대화로. 스마트폰 하나로 일자리 탐색 가능
- **정책 부합** — 2026년 노인일자리 115만 개 사업의 실효성 제고. 일본 후생노동성의 6.9억엔 AI 고령자 일자리 프로그램과 같은 문제의식에 대한 한국형 해법

## 현재 상태

**서비스 자체는 정상 동작하는 라이브 상태이며, 자동갱신 파이프라인도 구축되어 있다.**

| 항목 | 상태 |
|---|---|
| 서비스 상태 | 정상 동작 (라이브) |
| 자동갱신 | 파이프라인 구축됨 |
| 공개 범위 | DB API 호출 비용 문제로 제한 운영 중 |

기술적으로는 완전히 동작하는 서비스다. 다만 SenuriService API 호출에 따른 DB 비용 부담으로 전체 공개는 제한적으로 운영하고 있다. 비용 문제가 해결되면 즉시 풀 스케일로 확장 가능한 상태다.
