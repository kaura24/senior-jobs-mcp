### 문제의 핵심

시니어 구직자가 겪는 현실:

- **공고는 분산되어 있다** — 노인일자리여기, 고용24, 복지로, 지자체 사이트... 어디서부터 찾아야 할지 모른다
- **마감된 공고가 섞여 있다** — 검색 결과에 마감된 공고가 버젓이 나온다. 일일이 열어봐야 알 수 있다
- **검색이 어렵다** — 복잡한 필터, 생소한 용어. "나에게 맞는 일자리"를 찾는 건 고역이다
- **고정관념이 있다** — 기존 서비스는 시니어를 "단순 업무" 대상으로만 취급한다

> **핵심 질문:** *"어느 동네에서, 뭘 하면서 일하고 싶으세요?"*
>
> 이 질문에 답하면, 현재 지원 가능한 일자리를 정확히 안내해주는 서비스가 없을까?

### 🔧 규칙 + AI 하이브리드 아키텍처

**"규칙은 정확성을, AI는 유연성을 담당한다"**

</div>

<table>
<tr>
<td width="50%">

#### 🛡️ 규칙이 담당 (정확성)
- 공고 유효성 판정 (모집 상태·기간·충돌 검사)
- 중복 제거, 날짜 정규화
- *이 영역은 AI의 판단에 맡기지 않는다*

| 검증 항목 | 규칙 |
|----------|------|
| 모집 상태 | 명시적 '접수중' |
| 접수 기간 | 시작일 ≤ 오늘 ≤ 종료일 |
| 날짜 유효성 | '상시'·누락·오류 제외 |
| 상태 충돌 | 목록-상세 충돌 시 제외 |

</td>
<td width="50%">

#### 🤖 AI가 담당 (유연성)
- **모호한 조건 해소**: "오전 시간대" → 구체 시간 변환
- **개인화 질문 전략**: 후보 분포 기반 동적 질문 선택
- **근거 문장 생성**: "왜 이 공고인지" 자연어 설명
- **편향 방지**: 연령 고정관념을 프롬프트 레벨에서 차단

> *"나이를 이유로 디지털 능력, 체력을 추정하지 않는다"*
> — 프롬프트에 명시된 기술적 제약

</td>
</tr>
</table>

### 🔌 MCP 도구

| 도구 | 용도 |
|------|------|
| `describe_search_options` | 저장 데이터 기반 선택지·분포·누락 항목 |
| `search_jobs` | 현재 희망조건으로 저장 공고 검색·페이지 조회 |
| `get_job_details` | 선택한 실제 공고 ID의 저장 목록·캐시 상세 요약 |

### 핵심 원칙 3가지

1. **정확성** — 유효 공고만 추천. 마감·시작 전·날짜 불명확 공고는 절대 추천하지 않음
2. **존중** — 연령 고정관념 배제. 나이를 이유로 능력을 추정하지 않음
3. **투명성** — 근거 있는 추천. 모든 추천에 "왜 이 공고인지" 명시, 미확인 정보는 "공고에 미기재"로 표시

### 정책 부합성

- 고령층 고용 활성화 정책 방향과 부합 (2026년 노인일자리 115만개 사업의 실효성 제고)
- 일본 후생노동성의 6.9억엔 AI 고령자 일자리 프로그램과 같은 문제의식 — **한국형 해법** 제시
